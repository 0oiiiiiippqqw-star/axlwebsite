# Развёртывание AXL Website (Vercel + Discord + Steam)

Сайт статический, но вход через Discord, профиль и список участников работают
через serverless-функции в папке `api/`. GitHub Pages их не запускает —
хостить нужно на **Vercel** (бесплатного тарифа хватает).

## 1. Discord-приложение (OAuth)

1. https://discord.com/developers/applications → **New Application** (например, «AXL Site»).
2. Вкладка **OAuth2**:
   - скопируй **Client ID** и **Client Secret**;
   - в **Redirects** добавь: `https://<твой-домен>/api/auth/callback`
     (домен появится после первого деплоя на Vercel, например `axl-website.vercel.app`;
     если подключишь свой домен — добавь и его).

## 2. Бот (данные участников)

1. В том же приложении → вкладка **Bot** → **Reset Token** → скопируй **Bot Token**.
2. Там же включи **Server Members Intent** (обязательно — иначе список участников не отдаётся).
3. Пригласи бота на сервер клана: OAuth2 → URL Generator → scope `bot` (права не нужны,
   хватает дефолтных) → открой сгенерированную ссылку и добавь бота на сервер.
4. Включи в Discord режим разработчика (Настройки → Расширенные) и скопируй:
   - **ID сервера** (ПКМ по названию сервера → «Копировать ID»);
   - **ID ролей** Combat / Support / Lead / Проверяющий (Настройки сервера → Роли → ПКМ → «Копировать ID»).

## 3. Steam (привязка аккаунтов) и хранилище

- **STEAM_API_KEY**: https://steamcommunity.com/dev/apikey (домен — твой сайт).
  Без ключа привязка тоже работает, но без ника/аватара/часов/уровня.
- **Upstash Redis** (бесплатно): https://console.upstash.com → Create Database →
  скопируй `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`.
  Нужен для **турниров** (без него вкладка «Турниры» покажет «хранилище не
  настроено») и для привязок Steam на всех устройствах (без него привязка
  живёт в куке браузера — только там, где её сделали).

## 3.1 Турниры

- Создавать, завершать и удалять турниры может **роль Owner** — отдельная
  Discord-роль (не связана с Combat/Support/Lead/Recruiter). Создай роль
  на сервере (например, «Owner») и укажи её ID в `DISCORD_ROLE_OWNER`
  (можно несколько ролей через запятую).
- Данные турниров лежат в Upstash Redis (ключ `axl:tournaments`).

## 4. Деплой на Vercel

1. Запушь репозиторий на GitHub.
2. https://vercel.com → **Add New Project** → импортируй репозиторий
   (Framework: **Other**, ничего не настраивая — корень раздаётся как статика,
   `api/` становится функциями).
3. Project → **Settings → Environment Variables**, добавь:

   | Переменная | Что это |
   |---|---|
   | `SESSION_SECRET` | длинная случайная строка (50+ символов) |
   | `DISCORD_CLIENT_ID` | из шага 1 |
   | `DISCORD_CLIENT_SECRET` | из шага 1 |
   | `DISCORD_BOT_TOKEN` | из шага 2 |
   | `DISCORD_GUILD_ID` | ID сервера клана |
   | `DISCORD_ROLE_COMBAT` | ID боевых ролей (можно несколько через запятую) |
   | `DISCORD_ROLE_SUPPORT` | ID саппорт-ролей, напр. Builder,Farmer,Electrical — через запятую |
   | `DISCORD_ROLE_LEAD` | ID лид-ролей (Коллер и т.п.), можно несколько через запятую |
   | `DISCORD_ROLE_RECRUITER` | ID роли «Проверяющий» (реклама/набор), можно несколько через запятую |
   | `STEAM_API_KEY` | (опционально) из шага 3 |
   | `UPSTASH_REDIS_REST_URL` | из шага 3 — нужен для турниров |
   | `UPSTASH_REDIS_REST_TOKEN` | из шага 3 — нужен для турниров |
   | `DISCORD_ROLE_OWNER` | ID Discord-роли, которая управляет турнирами (можно несколько через запятую) |

4. **Redeploy** после добавления переменных.
5. Вернись в Discord-приложение и проверь, что redirect
   `https://<домен>/api/auth/callback` совпадает с реальным доменом.

## Как это работает

- «Войти» → `/api/auth/discord` → Discord OAuth → httpOnly-кука сессии.
- `/api/me` — профиль: ник/аватар из Discord, роль и дата вступления с сервера клана
  (через бота), привязанный Steam. С сайта данные не редактируются.
- `/api/members` — живой список участников с ролями (кэш 60 секунд).
- «Привязать Steam» в профиле → Steam OpenID → SteamID сохраняется за Discord-аккаунтом.
- Счётчик участников на главной берётся из публичного API инвайта и работает без бэкенда.
